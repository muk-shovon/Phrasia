# Decision Log — Phrasia

_All decisions are recorded here with date, rationale, and consequences._

---

## D-001: Primary language = Python; UI = Reflex
- **Date:** 2026-11-19
- **Decision:** Use Python (not TypeScript/React) for everything. UI is Reflex-authored.
- **Rationale:** PRD explicitly requires Python-first and prohibits a separate Next.js/TypeScript frontend.
- **Consequences:** All logic, providers, and business code live in Python. Browser assets are generated by Reflex. Deployment must prove Reflex can work on Vercel.

---

## D-002: FreeLLMAPI as preferred initial Humanizer route
- **Date:** 2026-11-19
- **Decision:** Default provider adapter is FreeLLMAPI OpenAI-compatible gateway, with Gemini and Groq as secondary options.
- **Rationale:** Owner already uses FreeLLMAPI locally; keeps costs at $0 where possible; open standard avoids vendor lock-in.
- **Consequences:** Requires owner to have FreeLLMAPI running on localhost during dev; Gemini/Groq available as fallbacks.

---

## D-003: Chunk size based on token budget, not word count
- **Date:** 2026-11-19
- **Decision:** `Chunker` estimates chars per token (~3.5) and budgets input/output/token overhead rather than imposing a fixed word cap.
- **Rationale:** Master prompt forbids arbitrary small app-level word caps. Provider limits are token-based, not word-based.
- **Consequences:** Configurable `max_input_tokens` parameter allows tuning per provider/model; default 4000 input tokens with safety margin.

---

## D-004: Paid calls blocked by default, explicit authorization required
- **Date:** 2026-11-19
- **Decision:** Default `PAID_PROVIDERS_ENABLED=false`, `PAID_MONTHLY_BUDGET_USD=0`. `check_paid_authorization()` runs server-side before every paid request.
- **Rationale:** PRD non-negotiable constraint; prevents accidental billing.
- **Consequences:** Paid adapters exist in code but cannot fire unless owner flips both environment flag AND authorizes each job.

---

## D-005: Supabase PostgreSQL from migration day one
- **Date:** 2026-11-19
- **Decision:** No SQLite; migrate directly to Supabase-managed Postgres with versioned SQL migrations.
- **Rationale:** Architecture doc mandates Supabase from the beginning; ensures RLS and storage integration from the start.
- **Consequences:** Owner must create a Supabase Free project before deploying; local dev can use `supabase start` or skip DB-dependent tests.

---

## D-006: Protected spans via zero-width placeholder strategy
- **Date:** 2026-11-19
- **Decision:** Extract URLs, emails, code blocks, citations, and identifiers into unique placeholders before chunking; restore them after generation.
- **Rationale:** Prevents LLMs from altering URLs, codes, or citation markers that must stay intact.
- **Consequences:** Adds ~10–20% complexity to chunking pipeline but dramatically improves output fidelity for technical documents.

---

## D-007: Worker tick pattern over long-running daemon
- **Date:** 2026-11-19
- **Decision:** Vercel Function invokes bounded worker (claims 1–few chunks, persists, exits) triggered by Supabase Cron every minute.
- **Rationale:** Vercel Hobby functions have a 300-second hard limit; no long-lived processes allowed. Supabase Cron is not limited to once/day like Vercel Hobby Cron.
- **Consequences:** Job progress is eventually consistent (at most 1-minute lag); checkpoints survive cold starts and redeployments.

---

## D-008: Dual plagiarism distinction (local vs external)
- **Date:** 2026-11-19
- **Decision:** Separate Supabase-indexed local-corpus matching from external provider scanning; always label coverage correctly.
- **Rationale:** PRD and Architecture forbid calling local matching "Internet-wide plagiarism"; misleading users would violate trust.
- **Consequences:** Two distinct adapters and report types in the data model; UI shows scoped labels.

---

## D-009: No promise of detector evasion
- **Date:** 2026-11-19
- **Decision:** Prompts never instruct the model to evade detectors; humanizer framed as writing improvement, not circumvention tool.
- **Rationale:** Ethical and legal constraints; aligns with "Words, Refined." positioning.
- **Consequences:** System prompt explicitly forbids claiming detector passes or fabricating scores.

---

## D-010: Vercel deployment fallback documented
- **Date:** 2026-11-19
- **Decision:** If Reflex ASGI deployment on Vercel fails, fall back to static Reflex export + FastAPI Functions bridge.
- **Rationale:** Architecture doc mandates a proof-of-concept test and accepts the fallback without silently changing frameworks.
- **Consequences:** If fallback triggers, `DECISIONS.md` must record which approach was chosen and why.
